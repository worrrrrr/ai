## 0. หลักการ

ทุกอย่างมาจากข้อมูล/การตั้งค่า ไม่มีค่าตายตัว — สี/ระยะมาจาก token ใน `src/routes/layout.css`

## 1. โครงเปลือก (ใช้ร่วมทุกหน้า ยกเว้น `/auth`)

```
┌───────────────────────────────┬──────────────────────────────────────────────┐
│ SIDEBAR (ย่อ/ขยายได้)          │ เนื้อหา (children ของ route)                  │
│                               │                                              │
│ [✦ ai]              [ + ]     │  ┌────────────────────────────────────────┐  │
│ ─────────────────────────────  │  │                                        │  │
│  [หน้าแรก] [แชท] [เอเจนต์]    │  │        (แต่ละ route วาดส่วนนี้)         │  │
│  [โปรเจกต์]                    │  │                                        │  │
│ ─────────────────────────────  │  └────────────────────────────────────────┘  │
│  ▸ แชท A                      │                                              │
│  ▸ แชท B   ← กด = เปิด /chat/:id│  │                                        │  │
│  ▸ ···                        │  └────────────────────────────────────────┘  │
│ ─────────────────────────────  │                                              │
│  you@email                     │                                              │
│  ผู้ให้บริการ · พรอมป์ · สไตล์ ·│                                              │
│  เลย์เอาต์                     │                                              │
└───────────────────────────────┴──────────────────────────────────────────────┘
```

- **`[✦ ai]` = brand icon (Sparkles) ทำหน้าที่ panelLeft**: กดแล้วย่อ sidebar → `AppShell` ซ่อน sidebar แล้วโชว์ brand icon อันเดียวกันมุมซ้ายบนเพื่อกดขยายกลับ (ไม่ต้องมีปุ่ม panelLeft แยก)
- **เมนูหลักใน sidebar (4 อัน)**: หน้าแรก `/` (ไอคอน house) · แชท `/chat` (message-square) · เอเจนต์ `/agent` (bot) · โปรเจกต์ `/project` (folder)
  - active state ผูกกับ path: `/` ต้องตรงเป๊ะ; `/chat` ถือว่า active เมื่ออยู่ `/chat` หรือ `/chat/*`
- ปุ่ม `[ + ]` (Plus) = **ไปหน้าแรก `/`** (ช่องแชทเริ่มแชทใหม่) — **ไม่สร้างแชทว่างทันที** แชทจะเกิดเมื่อส่งข้อความแรกเท่านั้น (กันกดรัวแล้วได้แชทเปล่าเต็ม)
- แถบล่าง = อีเมลผู้ใช้ + ลิงก์เข้า `settings/*` (ถ้าไม่ล็อกอิน → โชว์ "เข้าสู่ระบบ")
- `/auth` **ไม่มีเปลือก**: `+layout.svelte` เช็ค path แล้วเรนเดอร์แค่ children

## 2. แผนที่การนำทาง (กดขยาย)

```
แอป
├─ /auth                      หน้าเข้าสู่ระบบ (ไม่มี sidebar)
│   └─ /auth/callback         แลก session แล้วกลับ
└─ (เปลือก) — ทุกหน้าอื่น
    ├─ /                      หน้าแรก = ช่องแชทเริ่มแชทใหม่  ← ไม่ redirect
    ├─ /chat                  ▸ รายการแชท
    │   └─ /chat/:id          ▸ เปิดแชท (header + ข้อความ + ช่องพิมพ์)
    ├─ /agent                 (ว่าง — scaffold)
    │   └─ /agent/:id         (ว่าง)
    ├─ /project               (ว่าง)
    │   └─ /project/:id       (ว่าง)
    └─ /settings                     (มีแท็บนำทาง 4 หมวด + ข้อความ "ทุกค่าปรับได้เอง")
        ├─ /settings/providers        ▸ เพิ่ม/แก้/ลบ + ทดสอบเชื่อมต่อ (รายชื่อโมเดลจริง)
        ├─ /settings/prompts          ▸ เพิ่ม/แก้/ลบพรอมป์ระบบ + ดูข้อความเต็ม
        ├─ /settings/styles           ▸ แม่แบบสี/มุม 12 ชุด + สร้างเอง + ตัวอย่างสว่าง/มืด

```

**หน้าแรก — `/`** (ช่องแชทกลางจอ แบบ ChatGPT)

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│                      เริ่มจากตรงไหนดี?                       │
│                                                             │
│         ┌───────────────────────────────────────┐           │
│         │ ถามอะไรก็ได้…                   [↑]   │           │
│         └───────────────────────────────────────┘           │
│                                                             │
│         [calc] ช่วยคิดเลข 128 × 46 ให้หน่อย                 │
│         [search] ค้นหาเรื่องที่อยากรู้จากเว็บ                │
│         [cloud] อากาศที่กรุงเทพตอนนี้เป็นยังไง               │
└─────────────────────────────────────────────────────────────┘
```

- ใช้ `Composer` โหมด `layout="hero"` (ไม่ dock) กลางจอ + หัวข้อด้านบน
- รายการแนะนำ: ไอคอน lucide (`calculator` / `search` / `cloud-sun`) — **กดแล้วเติมข้อความลงช่องพิมพ์** (ยังไม่ส่ง) ให้ผู้ใช้เห็น/แก้ก่อน
- พิมพ์/กดส่ง → สร้างแชททันที (id ฝั่ง client → `/api/chat` เรียก `ensureChat`) แล้วเด้งไป `/chat/:id` เมื่อจบคำตอบแรก

## 3. หน้ารายการแชท — `/chat`

```
┌ แชทของฉัน ───────────────────────────────── [ เริ่มแชทใหม่ ] ┐
│                                                             │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ ชื่อแชท………                      [ชื่อแชท] [เปลี่ยนชื่อ] [ลบ]│ │
│ └─────────────────────────────────────────────────────────┘ │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ ชื่อแชท………                      [ชื่อแชท] [เปลี่ยนชื่อ] [ลบ]│ │
│ └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

- ปุ่ม "[ เริ่มแชทใหม่ ]" = ลิงก์ไป `/` (ช่องแชท) ไม่ใช่การสร้างแชทว่างทันที
- ชื่อแชท (ซ้าย) = ลิงก์เปิด `/chat/:id` · ด้านขวามีฟอร์มเปลี่ยนชื่อ + ลบ (ทำงานแบบ form POST)
- สถานะว่าผลาด้านบนแสดงด้วย `role="alert"` สี danger
- ว่างเปล่า → "ยังไม่มีแชท" กลางจอ

## 4. หน้าแชท — `/chat/:id`

```
┌ ชื่อแชท……… ─────────────────────────────────── [รายการแชท] ┐
│                                                            │
│        ┌──────────────────────────────────────────┐        │
│        │ คุณ                             [copy]   │        │
│        │ ข้อความของผู้ใช้ (bg-brand-soft)           │        │
│        └──────────────────────────────────────────┘        │
│  ┌─────────────────────────────────────────────┐           │
│  │ ผู้ช่วย                            [copy]     │           │
│  │ ข้อความตอบกลับ (bg-surface)                  │           │
│  │  ▸ ใช้เครื่องมือ search · output-available    │           │
│  └─────────────────────────────────────────────┘           │
│                        (เลื่อนอัตโนมัติเมื่อติดล่าง)          │
├────────────────────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────────┐ [↑ / ■]   │
│ │ พิมพ์ข้อความ…                                  │           │
│ └──────────────────────────────────────────────┘           │
└────────────────────────────────────────────────────────────┘
```

- ข้อความผู้ใช้ชิดขวา (`items-end`) ข้อความผู้ช่วยชิดซ้าย
- `▸` = กดขยายดู tool / การคิดของโมเดล (รายละเอียดด้านล่าง)
- ช่องพิมพ์: Enter = ส่ง, Shift+Enter = ขึ้นบรรทัด, IME-safe (ไทย)
- ระหว่างสตรีม ปุ่ม `[↑]` เปลี่ยนเป็น `[■]` = หยุดคำตอบ
- **พิมพ์ `/` → เปิดเมนูคำสั่ง** (คำนวณ / ค้นหา / อากาศ) ลูกศรเลื่อน, Enter เลือก, Esc ปิด
  - เลือกแล้วได้ **chip** เหนือช่องพิมพ์ (hover ดู tooltip คำอธิบาย, กด × เพื่อเอาออก)
  - **ทุกอย่างส่งตอนกดส่งเท่านั้น** — เลือกคำสั่งไม่ส่ง, `commands` แนบไปกับ body ของ request
  - ฝั่ง server: ถ้ามี `commands` จะ **ข้าม Tev1** และใช้ tool ที่สั่ง (`strategy: 'forced'`)
- `@` (ชี้เป้า/อ้างอิง เช่น `@agent`) ยังไม่ทำ — ต้องมี agent/project จริงก่อน ไม่งั้นเป็นของประดับ

**อัปเดต 2026-10-15 (ตรวจจากโค้ดจริง — แผนภาพด้านบนยังเป็นของเดิม):**

- แถบหัว: ชื่อแชท **แก้ได้ทันที** (input → Enter เพื่อบันทึก ผ่าน action `rename`) · มี **chip "ใครตอบ"** (ผู้ให้บริการ · โมเดล จาก `metadata` ของข้อความล่าสุด)
- แถบหัวด้านขวา = **การกระทำของแชท** (ไอคอน): คัดลอกทั้งแชท (เป็นเครื่องหมายถูก 2 วินาที) · รายการแชท · **ลบแบบ soft delete พร้อมกล่องยืนยัน**
- ปุ่ม `[copy]` ย้ายไป **ท้ายข้อความ** (ไม่ใช่แถวหัวชื่อ) · ข้อความผู้ช่วยมีบรรทัด `ผู้ให้บริการ · โมเดล · เวลา` ต่อท้าย (จาก `duration_ms`)
- ใต้คำตอบมีบรรทัด **ขั้นของคำขอ** (`data-route`): กลุ่มที่ router เลือก + คะแนน · เครื่องมือที่ส่ง · โมเดล — **ขึ้นสีแดงพร้อมเหตุผลเมื่อ router ล้ม**
- สถานะเครื่องมือแสดงเป็น **ภาษาไทย** แล้ว (`กำลังเตรียม` · `กำลังทำ` · `เสร็จแล้ว` · `ผิดพลาด`) ไม่ใช่ `output-available`

## 5. ส่วนประกอบของข้อความ (กดขยาย)

```
ข้อความหนึ่ง (Message.svelte)
├─ แถวหัว: [ชื่อบทบาท] [copy]
└─ กล่องข้อความ (MessageParts.svelte) — แยกตาม part.type จริงจาก AI SDK
    ├─ text        → ย่อหน้าปกติ
    ├─ reasoning   → ▸ การคิดของโมเดล         (กดขยาย)
    ├─ tool-<ชื่อ> → ▸ ใช้เครื่องมือ <ชื่อ> · <state>  (กดขยายเป็น JSON: input/output/error)
    └─ อื่น ๆ      → ▸ ส่วนข้อมูล: <type>      (ไม่ให้ข้อมูลหายเงียบ ๆ)
```

**ห้ามฝังชื่อ tool ตายตัว** — UI อ่านจาก `part.type` จริง จึงรองรับ tool ใหม่ทันทีที่ไม่แก้ UI

## 6. Component tree (ใครเรียกใคร)

```
+layout.svelte
├─ (chromeless ถ้า /auth) → children
└─ AppShell
    ├─ Sidebar            (header / รายการแชท / footer)
    └─ children (route)
        ├─ /chat         → การ์ดแชท + ฟอร์ม
        └─ /chat/:id     → MessageList → Message → MessageParts
                           Composer
```

## 7. ยังไม่มี (scaffold ว่าง)

`/agent`, `/agent/:id`, `/project`, `/project/:id` รวมถึง component ที่ผูกกับมัน (AgentCard, Markdown, toast, skeleton)
— ดูแผนใน `PLAN.md` เฟส 3 (T3.5) และเฟส 5

หน้า `/settings/*` ทั้ง 4 หมวด **ทำแล้ว** (ดู §9) พร้อม component ที่ใช้ร่วมกัน:
`SettingsPanel` (การ์ดหัวข้อ), `SettingsAlert` (error/success/info), `StyleFields` (ช่องค่าทุกโทเค็น),
`StylePreview` (ตัวอย่างสว่าง/มืด), `StyleRowEditor` (ฟอร์มแก้ไขทีละสไตล์)

## 8. สถานะที่ UI ต้องมี (เช็คลิสต์)

- ข้อความว่าง / ยังไม่มีแชท / ยังไม่ล็อกอิน — **มีแล้ว**
- กำลังส่ง/สตรีม + ปุ่มหยุด — **มีแล้ว**
- ข้อผิดพลาดจาก action (`role="alert"`) — **มีแล้ว**
- ยังไม่มี: toast, skeleton, ปุ่มลองใหม่แบบรวมศูนย์, markdown render + sanitize
- **อัปเดต 2026-10-15:** มีหน้า error ภาษาไทยระดับแอปแล้ว (`src/routes/+error.svelte` — แสดงรหัสสถานะ/เหตุผล + ทางกลับหน้าแรก) และใต้คำตอบมีบรรทัด **ขั้นของคำขอ** ที่จะ**ขึ้นสีแดงพร้อมเหตุผลเมื่อ router ล้ม** → ส่วน "ปุ่มลองใหม่แบบรวมศูนย์" มีในระดับหน้า error · **toast · skeleton · markdown render + sanitize ยังไม่มี** (ตามเดิม)

## 9. หน้า settings (4 หมวด) — ทำแล้ว

```
┌ ตั้งค่า ────────────────────────────────────────────────────────────┐
│ [ผู้ให้บริการ] [พรอมป์] [สไตล์] [เลย์เอาต์]      ← แท็บ (aria-current) │
│ ┌ ── การ์ดหัวข้อ (SettingsPanel) ──────────────────────────────────┐ │
│ │ หัวข้อ + คำอธิบายสั้น                          [ การทำงานของหมวด ] │ │
│ │ เนื้อหา: ฟอร์ม / รายการ / แม่แบบให้เลือก                          │ │
│ └──────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────┘
```

- **สไตล์** — คลังแม่แบบ 12 ชุด (น้ำเงิน/มรกต/เขียวน้ำทะเล/ม่วง/ม่วงแดง/ชมพู/อำพัน/ดินเผา/เทาโมโน/
  คอนทราสต์สูง/โค้งมน/เหลี่ยมเรียบ) แสดงตัวอย่างสี 6 ชิป (สว่าง 3 / มืด 3) ต่อการ์ด
  - “ใช้เลย” = คัดลอกค่าลงตาราง `styles` แล้วตั้งเป็นสไตล์หลัก (กดซ้ำได้ ไม่สร้างแถวซ้ำ)
  - “คัดลอกมาแก้” = เติมค่าลงฟอร์มสร้างเอง ยังไม่บันทึกจนกว่าจะกดปุ่ม
  - เลือก **สีหลักสีเดียว** จากจานสีอิสระ (`<input type="color">`) หรือพิมพ์ hex/oklch แล้ว **คำนวณอีก 5 สีให้**
    (`src/lib/colorPalette.ts`: hue คงเดิม, chroma/lightness ถูกจำกัดช่วงให้อ่านออกทั้งสองโหมด)
  - มีแถบค้นหาสีสำเร็จรูป 12 สี (ค้นได้ทั้งชื่อไทยและรหัสสี) และค้นหาแม่แบบ 12 ชุด
  - ยังกำหนดสีทีละค่าทั้ง 6 + มุมการ์ด/มุมคอนโทรลเองได้ใน “ขั้นสูง” (พับไว้ ไม่กินพื้นที่)
- **เลย์เอาต์** — ทุกแกนเลือกจาก **แผ่นไอคอน** (lucide) แทนปุ่มข้อความ และมีช่องพิมพ์ค่าเองกำกับทุกแกน

  | แกน                  | ไอคอน (เรียงตามระดับ)                                                                                                                   |
  | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
  | ธีม                  | `sun` · `moon` · `sun-moon`                                                                                                             |
  | รูปแบบแถบด้านข้าง    | `panel-left` ชิดขอบ · `layout-dashboard` ลอย (ช่องว่างรอบ+มุมโค้ง+เงา) · `columns-3` อินเซ็ต (พื้นเปลือกเป็นสีรอง เนื้อหาเป็นการ์ดโค้ง) |

ทุกหมวดมีสถานะ: กำลังโหลด (ค่าเริ่มต้นจาก server), ว่าง (“ยังไม่มี…”), error (`role="alert"`),
สำเร็จ (`role="status"`), และข้อความแนะนำให้รัน migration เมื่อยังไม่มีตาราง

**หลักการตอบสนอง: กดแล้วเห็นผลทันที (แบบ VS Code / OpenAI) — ไม่มีปุ่มยืนยันแยก**

- แผ่นไอคอน/ชุดสำเร็จรูปในหน้าเลย์เอาต์: กดแล้ว submit ฟอร์มเองทันที (`requestSubmit`) พร้อม `use:enhance`
  - `invalidateAll` → เปลือกแอปจริงอัปเดตโดยไม่ต้องรีเฟรชหน้า
- หน้า `/settings/styles`: **กดรายการในกรอบซ้าย = ใช้สไตล์นั้นทันที** (ฟอร์มลับยิง `?/apply` หรือ `?/use`
  หลัง `tick()` เพื่อให้ action/ค่าที่ซ่อนอัปเดตก่อน) · ช่องสีใน “ขั้นสูง” ส่งค่าตอนออกจากช่อง (`change`)
- หลังเขียนค่า ฝั่ง server **อ่านกลับมาตรวจ** ว่าค่าติดจริง (`verifyActiveStyle`) — ถ้าไม่ติดจะตอบ error
  แทนการขึ้น “สำเร็จ” ปลอม
- providers/prompts ยังเป็นฟอร์มที่ต้องกดปุ่มยืนยัน (เป็นการเพิ่ม/ลบข้อมูล ไม่ใช่การปรับหน้าตา)

**อัปเดต 2026-10-15 (ตรวจจากโค้ดจริง):**

- `providers` และ `prompts`: **ฟอร์มเพิ่มถูกซ่อนไว้หลังปุ่ม** มุมขวาบน (`aria-expanded` · ข้อความปุ่มสลับเป็น "ปิดฟอร์ม") → เปิดหน้าเห็น **รายการ** เป็นเนื้อหาหลัก (เดิมฟอร์มยาวกินครึ่งจอแรก) · การยืนยันก่อนบันทึกยังเหมือนเดิม (บรรทัดข้างบนยังจริง)
- หน้าเลย์เอาต์: **แกนถูกจัดเป็น 3 กลุ่ม** แล้ว มีหัวข้อคั่นในกรอบซ้าย — `โครงและธีม` (ธีม · ด้าน · รูปแบบ) · `สัดส่วน` (ความกว้าง · ความหนาแน่น · คอลัมน์ · สเกลจอ) · `การย่อ` (เริ่มต้น · วิธีย่อ) โดยตารางไอคอนด้านบนยังถูกต้องทุกแถว
- กรอบโฟกัสคีย์บอร์ด: คืนค่า `:focus-visible` (สีแบรนด์) ให้ช่องกรอก **19 จุด** ทั่วแอป (เดิมถูก `outline-none` ปิด) · ลิงก์เมนูในโหมดย่อมี `aria-label` + `title` แล้ว (สำคัญเพราะ `rail-hide` ใช้ `display:none`)

**ข้อขัดแย้งในเอกสารที่พบ (ยังไม่แก้ — รอเจ้าของตัดสิน):** บรรทัดก่อน ๆ มีทั้ง _"เลือกธีมแล้วเปลี่ยนทันที … ยังไม่บันทึกจนกด 'บันทึกค่า'"_ และ _"กดแล้วเห็นผลทันที (แบบ VS Code) — ไม่มีปุ่มยืนยันแยก"_ ซึ่งขัดกัน — ของจริงคือ **กดแล้วบันทึกทันที** (`enhanceAll` + `invalidateAll`) จึงควรตัดข้อความที่บอกว่าต้องกด "บันทึกค่า" ออก แต่ผมไม่แก้ข้อความเดิมของเจ้าของเอง
