## 2. ทำไม "เราถึงไม่มี" (ตอบตรง ๆ)

DSH เป็น **runtime ของเอเจนต์** (คุมกระบวนการทำงานของ AI: ทีม เป้าหมาย งานเบื้องหลัง สกิล อนุมัติ) ส่วนแอปเราเป็น **แอปแชทหลายผู้ใช้** (คุมข้อมูล: แชท เอเจนต์ โปรเจกต์ สิทธิ์) — คนละชั้นกัน จึงไม่แปลกที่ของบางอย่าง DSH มีแต่เราไม่มี และของบางอย่าง (auth หลายผู้ใช้, deploy เว็บ) เรามีแต่ DSH ไม่มี

สิ่งที่ลอกได้ = ชิ้นส่วนระดับ "กระบวนการ" ที่ไม่ขัดกับแอปแชท

## 3. ลอกอะไรก่อน (เรียงตามคุ้ม/เล็ก)

| ลำดับ | ลอกอะไร                                                                                                                       | ขนาด | ได้อะไรกับผู้ใช้                                               |
| ----- | ----------------------------------------------------------------------------------------------------------------------------- | ---- | -------------------------------------------------------------- |
| 1     | **รายการงานระหว่างทาง (todo)** — เก็บขั้นของรอบลงตาราง (`orchestration_steps` มีอยู่แล้ว) แล้วโชว์เป็นข้อ "กำลังทำ/เสร็จ/ล้ม" | S    | เห็นความคืบหน้าแทนการรอเงียบ (ต่อจากสตรีมที่มีแล้ว)            |
| 2     | **ทีมถาวร (Agent Teams)** — ตาราง `agent_teams` + `team_members` (ติ๊กหัวหน้าได้) แทนการเลือกใหม่ทุกครั้ง                     | M    | เรียกทีมเดิมซ้ำได้ ตั้งชื่อทีมได้ ("ทีมรีวิวโค้ด")             |
| 3     | **งานเบื้องหลัง** — ตาราง `jobs` + สถานะ queued/running/done/failed + หน้า list                                               | M    | ปิดแท็บได้ กลับมาแล้วผลยังอยู่ (สำคัญกับรอบที่ใช้เวลาเป็นนาที) |
| 4     | **เป้าหมายยาว** — ตาราง `goals` (objective/status/rounds) ผูกกับแชท แล้วให้ระบบ "ทำต่อ" เป็นรอบ                               | L    | งานยาวไม่ต้องพิมพ์ซ้ำทุกครั้ง                                  |
| 5     | **สกิล/ชุดคำสั่ง** — ตาราง `skills` (ชื่อ/พรอมป์/เครื่องมือที่อนุญาต) เลือกใช้ต่อแชท                                          | M    | เพิ่มความสามารถโดยไม่ต้องแก้โค้ด                               |
| 6     | **ขั้นอนุมัติ** — ก่อน action ที่มีผลข้างเคียง (ลบ/เขียนไฟล์/ใช้เครื่องมือเสียเงิน)                                           | M    | กันพลาดและคุมค่าใช้จ่าย                                        |
| 7     | **ปลั๊กอิน + ภาพ/เอกสาร**                                                                                                     | L    | ขยายได้เอง · สร้างภาพ/PPTX จากแชท                              |

**แนะนำเริ่มที่ 1 → 2 → 3** (เล็กไปใหญ่ ได้ผลเร็ว และต่อยอดจาก orchestrator ที่มีอยู่แล้วโดยไม่รื้อ)

## 4. เรื่องที่ต้องตัดสินก่อนทำข้อ 3-4

- งานเบื้องหลังต้องมีที่รัน: Cloudflare Workers ไม่มี process ค้าง — ต้องใช้ **Queues/Cron Triggers/Durable Objects** (มี skill `durable-objects`, `wrangler` ในเครื่องนี้ช่วยได้)
- เป้าหมายยาว = ต้องมีเพดานรอบ/เพดานค่าใช้จ่ายต่อเป้าหมาย และปุ่มหยุดที่ชัดเจน
- ขั้นอนุมัติ = ต้องมีคิวการอนุมัติใน UI (จะเพิ่ม "การรอ" กลับเข้ามา — ต้องออกแบบให้ไม่รบกวน)
