## 2. สองโหมดที่เป็นไปได้ (ต้องเลือก)

### โหมด A — Orchestrator อยู่ในแอป (feature จริงของผู้ใช้)

ต่อจากหน้า `/agent`: ผู้ใช้เลือก "ชุดผู้เชี่ยวชาญ" (2-4 ตัว) แล้วแชทหนึ่งรอบจะ:

1. **วางแผน** — โมเดลเร็ว (`experimental_decide`/`fast_model`) เลือกว่าจะถามใคร และถามอะไร (แตกงานเป็นชิ้น)
2. **ทำงานขนาน** — ยิงแต่ละเอเจนต์พร้อมกัน (`Promise.all`) ด้วยโมเดล/พรอมป์ของตัวเอง · เครื่องมือของแต่ละคนยังใช้ได้
3. **รวมคำตอบ** — เอเจนต์หัวหน้า (lead) อ่านคำตอบทั้งหมด + แหล่งที่มา แล้วเขียนคำตอบเดียว
4. **แสดงร่องรอย** — UI ต้องเห็นว่าใครพูดอะไร (ใช้ `MessageParts` แบบ generic + `agent_id`)

สิ่งที่ต้องเพิ่ม: ตาราง `orchestrations` (หรือคอลัมน์ใน `chats`) เก็บชุดเอเจนต์ที่เลือก + สถานะแต่ละขั้น, endpoint/สตรีมแบบใหม่, UI เลือกชุดเอเจนต์ + แสดงร่องรอย
ความเสี่ยง: ต้นทุนโมเดลคูณจำนวนเอเจนต์ · ต้องมี timeout/ยกเลิกกลางทาง · คำตอบมาช้า (ขนานช่วยได้)

### โหมด B — ใช้ DSH เป็น orchestrator (ไม่เพิ่ม feature ในแอป)

งานพัฒนา/วิเคราะห์ของโปรเจกต์นี้ให้ DSH (Agent Teams / workflow / expert teams) เป็นคนจัดทีมทำงาน แล้วเอา "ผล" มาลงแอป
ข้อดี: ไม่แตะสคีมา/ไม่กินโควตาโมเดลของผู้ใช้ในแอป · ข้อเสีย: ผู้ใช้ปลายทางในแอปไม่ได้ orchestrator (เป็นเรื่องของ process เราเท่านั้น)

## 3. สัญญาที่จะไม่แตะ (เพื่อความเข้ากันได้)

- `streamText` + `toUIMessageStream` ยังเป็นทางเดียวที่ client เห็น (เพิ่ม "ขั้น" เป็น message parts ไม่ใช่ช่องทางใหม่)
- ทุกข้อความที่บันทึกยังมี `model`, `provider`, `agent_id`, tokens/duration ตามคอลัมน์จริง
- กติกาเดิม: ไม่ mock · ข้อความไทย · Svelte 5 runes · ใช้โทเค็นใน `layout.css` · ห้าม secrets ลงฐานข้อมูล

## 4. เกณฑ์ผ่านเมื่อสร้างจริง (โหมด A)

1. เลือกชุดเอเจนต์ในแชทได้จริง และค่าติดไปกับ `chat_participants` ของแชทนั้น
2. หนึ่งคำถาม → ได้คำตอบที่ผ่านการรวมจาก N เอเจนต์ พร้อมร่องรอยว่าใครตอบอะไร (เห็นใน UI)
3. เอเจนต์ตัวใดล้ม (โมเดลไม่ตอบ/หมดเวลา) → รอบนั้นยังจบได้ และ UI บอกว่าใครล้ม
4. ยกเลิกกลางทางได้ และส่วนที่เสร็จถูกบันทึก (ตามแบบ `onEnd` ที่ใช้อยู่)
5. `pnpm check` 0 errors 0 warnings · `pnpm test` ผ่าน · `pnpm lint` ผ่าน · มีเทสต์ของ "การวางแผน/การรวม" ที่ไม่ต้องพึ่งโมเดลจริง

## 5. คำถามที่ต้องตอบก่อนลงมือ

1. เอา **โหมด A** (สร้างในแอป) หรือ **B** (ใช้ DSH จัดทีม) หรือทำ A แบบย่อ (ไม่มี lead รวมคำตอบ แค่ตอบขนานแล้วโชว์)
2. จำนวนเอเจนต์สูงสุดต่อรอบ (แนะนำ 3) และมี "เพดานค่าใช้จ่าย/เวลา" เท่าไร
3. ใครเป็นหัวหน้ารวมคำตอบ: เอเจนต์ที่ผู้ใช้ติ๊ก "หัวหน้า" หรือโมเดลหลักของระบบ
